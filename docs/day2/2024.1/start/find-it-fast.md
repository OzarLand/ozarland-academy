## Where the final-objective questions are answered

| Question | Short answer | Details |
|---|---|---|
| If I execute a specific tag, exactly what happens? | The tagged plays run on all their hosts. The haproxy frontend of that service, if it has one, is re-rendered (and, with `haproxy_single_external_frontend`, its block of the external frontend map). `common` does not run: in 2024.1 it is still its own play, tagged `common` only (`site.yml:88-103`). For API services, Keystone registration and DB-sync containers run (Neutron's included, on `deploy` and `reconfigure`: `roles/neutron/tasks/bootstrap_service.yml:2-21`). Handlers restart drifted containers, plus their role siblings [CODE] | [Tags §3](../risk/tags.md#3-what-a-tag-really-executes-master-table), [Reconfigure a single service §2](../operations/reconfigure-a-service.md#2-execute-a-service-specific-tag-implicit-effects), [Components](../components/index.md) |
| Which OpenStack components are affected? | The tagged service, plus HAProxy (only if its frontend changed). fluentd/cron/kolla_toolbox only under `-t common` or a run without tags (if `common` drifted) [CODE] | [Reconfigure a single service §2](../operations/reconfigure-a-service.md#2-execute-a-service-specific-tag-implicit-effects) |
| Which compute nodes will receive changes? | Every compute in the play's host patterns (`common`, `nova`, `nova-cell`, `neutron`, `openvswitch`, `iscsi`, …) runs the tasks (`nova.yml:125-147`, `site.yml:611-624, :671-693`). Restarts happen where drift exists, usually all or none, because inputs are global [CODE] | [Compute scaling §2](../concepts/compute-scaling-and-performance.md#2-work-per-compute-host-read-from-the-task-files), [Reconfigure Nova §4](../operations/reconfigure-nova.md#4-are-all-compute-nodes-affected-does-nova-compute-restart-on-every-compute) |
| Will containers restart or be recreated? | Restart (systemd unit restart, stop timeout `docker_graceful_timeout`, 60 s, `group_vars/all.yml:139`) on config drift. Recreate on image or parameter change. Siblings in the same role restart too. On a run with nothing to apply, a restart needs a notifying task that reports changed, and `check-containers` reports changed only for a missing container, a differing compared parameter, a missing or differing systemd unit file, or drift reported by `kolla_set_configs --check` (`module_utils/kolla_container_worker.py:58-65`). With Docker, drift is exit 1 or 137 or a client error, and a stopped container counts as drift (`module_utils/kolla_docker_worker.py:146-181`); with Podman, a container that is not running is drift and exit 1 is drift, while any other code fails the task (`module_utils/kolla_podman_worker.py:428-453`) [CODE]. Whether no notifying task reports changed on an unchanged cloud is [NOT AVAILABLE], with known exceptions [CODE]: containers whose `config.json` has an entry that `kolla_set_configs --check` always reports as drift (e.g. `prometheus_server` once files exist under `/etc/kolla/config/prometheus/extras/`: that `preserve_properties` entry has no `perm`, `roles/prometheus/templates/prometheus-server.json.j2:16-21`) restart on every deploy/reconfigure, and on a cloud deployed by 2023.1 the first 2024.1 check restarts every container whose unit 2023.1 wrote ([F16](../reference/findings.md#f16)) | [Repository architecture §4.3](../concepts/repository-architecture.md#43-the-config--check--handler-pattern), [Tags §3](../risk/tags.md#3-what-a-tag-really-executes-master-table), [Tags §2.4](../risk/tags.md#24-loop-notify-one-changed-item-notifies-the-handlers-of-all-items-code), [Kolla images §3](../concepts/kolla-images.md#3-kolla_set_configs---check-what-it-compares-and-its-exit-codes), [Predict and inspect a run §2](../operations/predict-a-run.md#2-the-first-20241-run-on-a-cloud-deployed-by-20231) |
| Can running VMs be impacted? | The restarts that the study traces to running VMs include `nova_libvirt` (frequent, via loop-notify), OVS/vswitchd and the L3 agent [CODE]. Whether VMs survive a libvirt restart, and whether their traffic is interrupted, is [NOT AVAILABLE] | [Nova deep dive §5](../components/nova-deep-dive.md#5-nova-libvirt-why-its-restart-is-special), [Risk register](../risk/risk-register.md) [R1](../risk/risk-register.md#r1)/[R6](../risk/risk-register.md#r6)/[R7](../risk/risk-register.md#r7), [Open questions](../troubleshooting/open-questions.md) [Q1–Q4](../troubleshooting/open-questions.md#q1) |
