# Troubleshooting

Where to look when a `kolla-ansible` run did something unexpected, or did nothing. Each row of the [symptom
index](#symptom-index) names what an operator sees, restates what the study says the code does, and links to the section
that establishes it. The page also says where to look for one component, what is already known as a bug or as an open
point, and which checks the study names.

> [!IMPORTANT]
> The study rests only on reading source code: kolla-ansible `2023.1-eol`, the kolla image repository `2023.1-eol`,
> ansible-collection-kolla `2023.1-eol` and the ansible-core 2.14.18 source. Nothing was run against a host, there are
> no timings, and every statement about data-plane or VM impact is [NOT AVAILABLE] ([Limits of this
> study](../reference/method-and-limits.md#limits-of-this-study)). All conclusions come from the 2023.1 implementation,
> not from Ussuri or from newer releases. Where a row says "no longer", "fixed" or "changed in 2023.1", it keeps a
> symptom that the Ussuri code produced and says what the 2023.1 code does instead.
>
> During an incident, the portal can tell what Kolla will do given the inputs: tasks and restarts. What that does to VMs
> and APIs depends on the environment and is mostly [NOT AVAILABLE] in these sources ([Code guarantees and environment
> dependence](../operations/index.md#code-guarantees-and-environment-dependence)).
>
> This page is an index. It adds no diagnosis and no procedure of its own.

## Symptom index

Three mechanisms explain almost every surprise on the operation pages: config drift means a full container stop/start,
never a reload; loop-notify, where one changed container in a role's loop restarts every container of that role on that
host; and global inputs, which are rendered into per-host files on every host ([Three mechanisms that explain almost
every surprise](../operations/index.md#three-mechanisms-that-explain-almost-every-surprise)).

In the tables, "What the code does" restates what the sections linked under "Read" say, and keeps their evidence labels.
Rows that restate a fact sheet carry the words of the fact sheets, FACT and NOT AVAILABLE, which name the same two
levels as [CODE] and [NOT AVAILABLE] ([Evidence labels](../start/conventions.md#evidence-labels)); for 2023.1 each such
row was checked against the 2023.1 code, and where the code is cited in the row it carries [CODE]. A sentence without a
label restates a sentence that carries none.

### Cases the study does not solve

The study does not diagnose a runtime failure of OpenStack, such as a failed VM deployment: no container or VM behaviour
is used as evidence ([Limits of this study](../reference/method-and-limits.md#limits-of-this-study)). For these classic
cases it offers the dependencies and the restarts read from the code, and marks the rest as open.
