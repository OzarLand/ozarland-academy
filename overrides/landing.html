Why this project exists

The Kolla-Ansible documentation tells you which command to run. Operating a platform also requires knowing what that command executes: which plays and tasks run, which containers can restart, and what can go wrong. That knowledge is spread across playbooks, roles, handlers and container images, and it is hard to learn from them directly.

The purpose of this project is to make that learning easier. Each release is studied from its source code and explained in operator terms, page by page, from the concepts to the procedures. The goal is not only to give answers, but to help you build your own understanding of how Kolla-Ansible works.

Meet Lumo, your guide

Lumo walks beside you through the Academy: where you are in the journey, what to read next, and what to be careful about. Patient and honest, Lumo says so clearly when the source code does not establish something.

Why "Lumo"? The name comes from lumen, Latin for light. Like the lantern Lumo carries, the Academy sheds light on what Kolla-Ansible really does, one step at a time.

How it helps you learn

  • Learn from the code itself

    A statement labelled [CODE] cites the path:line of the source it comes from. Open the file next to the page and you learn to read the playbooks yourself.

  • Know where knowledge stops

    What the sources do not establish is labelled [NOT AVAILABLE] instead of being guessed. You know exactly what is proven and what remains to be checked.

  • Understand before acting

    The concept pages explain the repository, the execution flow of a run and the kolla images, so that the operation pages make sense rather than being recipes to copy.

  • Compare the releases

    Each OpenStack release is a separate study with its own pages. Reading two of them shows how the behaviour of Kolla-Ansible changed from one release to the next.
