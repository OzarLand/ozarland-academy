    Three findings that look different between the 2024.1 study and the 2026.1 pages were read again in the source code of both releases (Kolla-Ansible 2024.1-eom and 22.2.0). With the default settings they behave the same in both, and the pages describe different sides of them:

    • Stopping a container. Each container runs under a systemd unit whose stop command is docker stop -t 60; if the container stops outside systemd, as with a plain docker stop, the unit starts it again after a delay computed from the container timeouts (ansible/module_utils/kolla_systemd_worker.py): 11 seconds with the Kolla-Ansible defaults, 59 seconds in the Quick lab, which sets docker_client_timeout: 600.
    • RabbitMQ quorum queues. On by default in 2024.1 (om_enable_rabbitmq_quorum_queues: true), written into each service’s configuration in 2026.1, where it can no longer be switched off.
    • MTU of tenant networks. Neutron takes the IP header and the tunnel header off the physical MTU; Kolla-Ansible sets the Geneve header to 38 bytes in both releases. On a 1500-byte network, that gives 1450 for VXLAN and 1442 for Geneve.

    This is a reading of the code, not a test. Other findings of the 2024.1 study have not been compared.
